# 品切れをその場で切り替える（店ごとの設定）

店員さんが `tools/menu/staff/?shop=<id>` で料理をタップすると、お客さんの画面（`app/?shop=<id>`）に1分ほどで「品切れ」と出る。品切れの状態は、店ごとに作る Google Apps Script（`soldout.gs`）が持つ。サーバーを借りる必要はなく、費用はかからない。

1店につき1回、京都ラボが次の手順で設定する。

## 手順

1. https://script.google.com で「新しいプロジェクト」を作り、名前を「お品書き 品切れ <店のID>」にする。`コード.gs` の中身を消して、`soldout.gs` をそのまま貼って保存する。
2. 左の歯車（プロジェクトの設定）→「スクリプト プロパティ」→ プロパティ `PIN`、値に店に渡す数字（6桁くらい）を入れて保存する。PIN はこのリポジトリやコミットに書かない。
3. 右上の「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。次のユーザーとして実行「自分」、アクセスできるユーザー「全員」でデプロイする。権限の確認が出たら許可する。出てきた `https://script.google.com/macros/s/…/exec` のURLを控える。
4. 左の時計（トリガー）→「トリガーを追加」→ 関数 `resetDaily`、イベントのソース「時間主導型」、「日付ベースのタイマー」で開店前の時間（例: 午前4時〜5時）にする。毎朝、品切れが全部もどる。いらなければ作らない。
5. `shops/<id>.json` に `"live": "<手順3のURL>"` を足す（編集画面の「店の情報」でも入れられる）。PR を出して `main` に入れる。
6. 店のスマホで `https://kyotolab.github.io/tools/menu/staff/?shop=<id>` を開き、PIN を入れる。ホーム画面に追加しておいてもらう。

## 確かめること

- ブラウザで手順3のURLを開くと `{"ok":true,"soldout":[],...}` が出る。
- 店員さんの画面で1品を品切れにして、別のスマホでお客さんの画面を開き直すと「品切れ」と出る。

## しくみ

- `GET` で品切れの料理IDの一覧を返す。お客さんの画面は、開いたときと、開いている間1分ごとに問い合わせる。つながらないときは `shops/<id>.json` の `soldout` のまま出す。
- `POST`（本文はJSON）で `{pin, action:"set", id, soldout}` か `{pin, action:"clear"}` を受ける。PIN を続けて20回まちがえると10分止まる。
- PIN を変えたいときは、手順2のプロパティを書き換えるだけでいい（デプロイし直さなくてよい）。`soldout.gs` を直したときは「デプロイを管理」から新しいバージョンにする（URLは変わらない）。
- デモ（`shops/demo.json`）は `"live": "demo"` で、同じブラウザの中だけで動く見本。PIN は 0000。
